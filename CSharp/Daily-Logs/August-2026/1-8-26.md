## 1 - 08 -26 // Properties

¿Esto representa un dato o una acción?

Si representa un dato, probablemente debería ser una Property.

Una propiedad se define como una herramienta que combina un getter (captador) y un setter (configurador) bajo un nombre compartido con un acceso similar al de un campo (field-like access)
Propósito: Permite obtener los beneficios de la ocultación de información y la abstracción (proteger los datos internos) manteniendo la simplicidad sintáctica de una variable o campo común

1. Definición y Funcionamiento Básico

    ¿Qué es una propiedad?: Es una herramienta que combina un getter (captador) y un setter (configurador) bajo un mismo nombre, permitiendo un acceso similar al de un campo (field-like access).
    Acceso simplificado: Desde fuera de la clase, se usan como campos (ej. objeto.Ancho = 3;), pero internamente ejecutan métodos que protegen los datos.
    El bloque get: Se encarga de devolver el valor y debe coincidir con el tipo de la propiedad.
    El bloque set: Se usa para asignar valores y tiene acceso a una variable implícita llamada value, que contiene el dato que se intenta asignar.

2. Propiedades Auto-implementadas (Auto-properties)

    Sintaxis concisa: El autor enseña que para casos donde no se requiere lógica extra, se puede usar public float Ancho { get; set; }.
    Backing Field automático: En estos casos, el compilador crea automáticamente una variable oculta (backing field) para almacenar el dato.

4. Inicialización Elegante

    Sintaxis de inicialización de objetos: Permite configurar propiedades inmediatamente después de la creación sin necesidad de múltiples constructores (ej. new Rectangulo() { Ancho = 2, Alto = 3 }).
    Accesorio init: Es un punto medio; funciona como un set pero solo durante la inicialización del objeto, permitiendo que la propiedad sea inmutable después de eso.

5. Tipos Anónimos

    El autor describe cómo crear objetos sobre la marcha sin definir una clase formal, usando var y la sintaxis de inicialización (ej. var persona = new { Nombre = "Steve", Edad = 34 };).

6. Filosofía del Autor

    Simplicidad vs. Protección: El autor insiste en que no debes usar campos públicos para evitar que el "mundo exterior" deje tus objetos en estados inconsistentes (como un rectángulo con área negativa).
