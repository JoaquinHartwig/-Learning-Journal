# Casting and Type Conversions

I learned the difference between:

## Implicit Conversion

Safe conversions that do not lose information.

Example:

```csharp
int number = 5;
double value = number;
```

## Explicit Conversion (Casting)

Used when data loss is possible.

Example:

```csharp
double value = 5.9;
int number = (int)value;
```

Result:

```text
number = 5
```

The decimal part is lost.

---

# Narrowing vs Widening Conversions

### Widening Conversion

Moves a value into a larger type.

Usually safe.

### Narrowing Conversion

Moves a value into a smaller type.

May lose information.

Example:

```csharp
int anInt = 300;
byte aByte = (byte)anInt;
```

This can produce unexpected results because `byte` cannot store values that large.

# Roundoff Errors

This was the most interesting concept I learned today.

Computers cannot always represent decimal numbers exactly.

For example:

```csharp
double number = 0.1;
```

Internally, this value is stored as an approximation.

### Famous Example

```csharp
double a = 0.1;
double b = 0.2;

Console.WriteLine(a + b == 0.3);
```

Many people expect:

```text
True
```

But the result can be:

```text
False
```

because floating-point numbers are approximations.

### Why It Happens

`float` and `double` follow the IEEE 754 floating-point standard.

Some decimal numbers have infinite binary representations.

The computer must cut the value and store the closest approximation.

### How To Handle It

Instead of:

```csharp
if(result == expected)
```

Use a tolerance:

```csharp
double tolerance = 0.000001;

if(Math.Abs(result - expected) < tolerance)
{
    // Close enough
}
```

### When To Use decimal

For financial calculations:

```csharp
decimal price = 19.99m;
decimal tax = 0.21m;
```

`decimal` provides much better decimal precision.

### Reflection

This topic made me realize something important:

Computers do not work with perfect mathematical values.

They work with finite representations stored in memory using bits.

Understanding limitations such as floating-point precision, memory representation, and data types feels like an important step toward becoming a better programmer.
